02 / A DIFFERENT KIND OF CHESS

Your partner changes
the position.

Red and Yellow face Blue and Green. Players move in a fixed cycle, so the engine must read a position through the lens of both its own king and its partner’s.

IronPhoenix supports four-player castling, promotion, en passant, and FEN position setup. Positive evaluation scores favor the team whose player is currently moving.

03 / PHOENIXNET

Built for this board.
Trained for this game.

PhoenixNet is IronPhoenix’s native NNUE evaluator, designed specifically for four-player Teams chess.

The v1 architecture combines 65,280 sparse input features with 17 king buckets and a shared 128-wide feature transformer. Own-king and partner-king streams feed a 256 → 32 → 32 → 1 dense network.

Place ironphoenix.nnue beside the executable to load it automatically. Without a network file, the engine falls back to handcrafted evaluation.

04 / GET STARTED

Build. Search. Learn. Rise.

Bring a C++20 compiler, CMake 3.24+, and Threads support.
MSVC, Clang, and GCC are supported.

01 / Build from source

git clone https://github.com/KnightStackSys/IronPhoenix.git
cd IronPhoenix
cmake -S . -B build -DIRONPHOENIX_BUILD_DATASET_GENERATOR=ON
cmake --build build --config Release

The Release configuration is used by multi-configuration generators such as Visual Studio. For a single-configuration generator, add -DCMAKE_BUILD_TYPE=Release to the configure command.

02 / Run a first search

uci
isready
setoption name Hash value 256
setoption name MultiPV value 4
position startpos
go depth 8

Launch the built ironphoenix executable, then enter these UCI-style commands. Set MultiPV to 1 for the normal single-line search.
