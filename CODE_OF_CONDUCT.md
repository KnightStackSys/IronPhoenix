# 🔥 IronPhoenix Code of Conduct

## 🛡️ Our Commitment

IronPhoenix is an open-source project focused on building and improving a high-performance four-player chess engine.

We want the project to be a place where people can collaborate, experiment, learn, review code, test ideas, and disagree constructively. Everyone participating in the IronPhoenix community is expected to help maintain a respectful, technical, and welcoming environment.

This Code of Conduct applies to contributors, maintainers, reviewers, testers, users, and anyone participating in project spaces.

---

## 🤝 Expected Behavior

Participants are expected to:

- Communicate respectfully and professionally.
- Critique ideas, code, benchmarks, and technical decisions rather than attacking people.
- Support technical claims with testing, measurements, examples, or reasoning when practical.
- Give constructive code-review feedback that helps improve the project.
- Be patient with contributors of different experience levels.
- Ask questions when requirements, rules, benchmarks, or engine behavior are unclear.
- Respect the complexity of four-player chess and recognize that reasonable technical approaches may differ.
- Keep discussions focused on the project when using project issue trackers, pull requests, discussions, and other development channels.
- Respect private information, credentials, unpublished work, and security-sensitive information.
- Give appropriate credit for code, research, testing, ideas, and other contributions.

---

## 🚫 Unacceptable Behavior

The following behavior is not acceptable:

- Harassment, threats, intimidation, stalking, or targeted abuse.
- Discrimination or derogatory comments based on personal characteristics or identity.
- Personal insults, name-calling, humiliation, or repeated hostile behavior.
- Sexual harassment or unwanted sexual attention.
- Publishing another person's private information without permission.
- Deliberately disrupting project discussions, reviews, testing, or development.
- Spamming issues, pull requests, discussions, or other project channels.
- Knowingly submitting malicious code, credential stealers, destructive payloads, or other harmful content.
- Misrepresenting benchmark results, test results, authorship, or contribution history.
- Plagiarizing code or knowingly violating software licenses.
- Using the project community to organize harassment or abuse elsewhere.

Strong disagreement about engine design, pruning techniques, evaluation, move ordering, architecture, benchmarks, or performance is allowed. Personal attacks are not.

---

## 🧪 Technical Discussions and Engine Testing

IronPhoenix development depends heavily on experimentation and strength testing.

When discussing engine changes:

- Treat Elo estimates, SPRT results, NPS, node counts, depth, and benchmark results as evidence rather than personal status.
- Clearly distinguish measured results from predictions or speculation.
- Prefer isolated testing when evaluating search heuristics or evaluation terms.
- Negative test results are useful information and should not be mocked or hidden.
- Reproducible tests are encouraged whenever practical.
- Do not knowingly falsify, selectively alter, or misrepresent testing data.
- Respect existing project behavior and comments when modifying established engine code unless the change intentionally replaces them.

A failed experiment is not a failed contribution. Good testing that shows an idea loses strength can still help the project.

---

## 🧑‍💻 Pull Requests and Code Review

When opening or reviewing a pull request:

- Keep the change focused when possible.
- Explain what the change is intended to accomplish.
- Include relevant testing information when available.
- Avoid unrelated rewrites in a feature-specific pull request.
- Review the implementation, not the contributor.
- Be willing to revise code when review identifies correctness, performance, maintainability, or testing concerns.
- Do not pressure maintainers to merge an experimental change before it has received appropriate review or testing.

Maintainers may request that experimental engine-strength changes remain on separate branches until testing is complete.

---

## 🌐 Scope

This Code of Conduct applies in official IronPhoenix project spaces, including:

- GitHub repositories
- Issues
- Pull requests
- Discussions
- Testing and benchmarking channels
- Project documentation
- Other communication spaces officially used for IronPhoenix development

It may also apply when someone is publicly representing the IronPhoenix project.

---

## 🚨 Reporting a Problem

If you experience or witness behavior that violates this Code of Conduct, report it to the IronPhoenix repository owner or project maintainers through an appropriate private GitHub contact method when possible.

Please include relevant information such as:

- What happened
- Where it happened
- When it happened
- Links, screenshots, or other evidence when available
- Any additional context that may help the maintainers understand the situation

Reports will be reviewed as fairly and confidentially as practical.

Do not knowingly submit false or retaliatory reports.

---

## ⚖️ Enforcement

Project maintainers are responsible for interpreting and enforcing this Code of Conduct.

Depending on the severity and history of the behavior, maintainers may take actions including:

1. **Correction** — A private or public request to change inappropriate behavior.
2. **Warning** — A formal warning that continued behavior may result in further action.
3. **Temporary restriction** — Temporary limits on participation in issues, pull requests, discussions, or other project spaces.
4. **Permanent ban** — Permanent removal from participation in IronPhoenix project spaces.

Severe behavior may result in immediate restriction or removal without first using every intermediate step.

Enforcement decisions should be based on protecting the project community and maintaining a productive development environment.

---

## 🧭 Maintainer Responsibilities

Maintainers are expected to:

- Apply this Code of Conduct consistently and in good faith.
- Avoid using enforcement as retaliation for technical disagreement.
- Distinguish heated technical debate from harassment or abuse.
- Protect confidential reports where practical.
- Remove, edit, or reject comments, commits, code, issues, or contributions that violate this Code of Conduct.
- Prioritize the safety and long-term health of the project community.

---

## 🔥 Project Values

IronPhoenix values:

**Performance. Correctness. Experimentation. Reproducibility. Respect.**

We can disagree aggressively about algorithms while still treating each other well.

♟️ **Build strong code. Test it honestly. Help the engine improve.**
